# map-route-service

地图点位与采集路线蓝图的独立项目。负责公共点位数据同步、本地缓存、名称查询、路线排序、官方底图渲染及 TRSS-Yunzai 消息输出，不修改 `Lotus-ReFactor`、`miao-plugin` 或 `Trss-Yunzai` 的源码。

## 当前能力(并未正常实现目标功能，待时补完)

- 同步官方中文地图点位、标签树和推荐路线。
- 使用哈希判断数据变化；下载失败保留旧缓存。
- 没有 ETag/Last-Modified 时使用内容哈希形成稳定版本，重复刷新不会重写 37 MB 数据文件。
- 原子写入 `data/markers.json` 与 `data/manifest.json`。
- 名称、别名、去标点和前缀匹配；宽泛结果先返回候选名称。
- 数据集常驻内存并建立精确名称索引，避免每次读取和解析完整 JSON。
- 按区域分组并用最近邻算法生成路线。
- 官方 P0 底图切片缓存、覆盖率检查与抽象路线图回退。
- TRSS-Yunzai 原生插件入口、每日刷新、顺序渲染和多图合并转发。
- 所有用户的地图渲染进入同一个全局队列，避免多个请求同时占用 Sharp 和底图下载。
- 每张图渲染前检查 Lotus 签到协调器；签到活跃时先等待签到完成。
- 缓存默认保留 30 天且限制为 512 MB，定时刷新后自动清理。

## 使用

```cmd
cd /d F:\Project\03_Game_Tools\Yunzai_Lotus\map-route-service
node src/cli.js refresh
node src/cli.js query 遗迹守卫
node src/cli.js route 水晶矿
```

数据源：HoYoLAB 官方静态地图接口。数据源不可用时，查询继续使用最近一次有效缓存。

## 接入 TRSS-Yunzai

将整个目录放到 Yunzai 的 `plugins/map-route-service`，在插件目录安装依赖并刷新一次数据：

```bash
cd /root/Yunzai/plugins/map-route-service
pnpm install --prod
node src/cli.js refresh
```

重启 Yunzai 后会从根目录 `index.js` 自动加载插件。当前指令：

```text
#gs遗迹守卫路线
#gs怪物路线 遗迹守卫
#gs材料路线 幽光萤石
#gs哪里有 水晶矿
#地图路线 晶蝶
#gs地图状态
#gs地图刷新        （主人）
#gs地图刷新强制    （主人）
#gs地图缓存清理    （主人）
#gs地图诊断        （主人）
#gs地图帮助
```

- 一张路线图直接回复；两张及以上使用与攻略消息相同的合并转发。
- 每页最多 40 个点位，图片逐张渲染，前一张结束后才开始下一张。
- 每天 `04:10:00` 检查官方数据；失败保留当前有效数据。
- 首次启动没有 `data/markers.json` 时自动初始化，也可提前执行刷新命令。
- 网络请求均带超时；本地数据会检查 JSON、点位数组、名称及坐标。
- 官方推荐路线存在时，结果末尾附带最多三条官方路线入口。

## 索引方案

当前采用“磁盘 JSON 原子快照 + 进程内精确名称索引”。首次加载约 37 MB 数据，之后相同数据直接复用内存对象；精确名称和别名使用 Map 命中，模糊查询再扫描规范化名称。这样避免引入 SQLite 原生模块及额外编译依赖，更适合 Yunzai 容器更新。实测同一进程中查询由首次约 528 ms 降至约 0.36 ms。

## 当前边界

- 官方推荐路线接口当前提供路线名称和入口地址，点位顺序详情未作为公开静态字段返回；图片中的顺序继续使用分区最近邻算法，结果末尾提供官方路线链接供对照。
- 地表优先使用官方 P0 底图。地下、群岛及覆盖不足区域明确使用坐标路线图，并在结果中注明回退页数，避免套用错误底图。
- Docker 内的真实群聊、私聊和合并转发仍需部署阶段验收。

渲染路线 SVG：`node src/cli.js render 遗迹守卫`，输出写入 `cache/`，同一数据和查询会命中缓存。

## 真实数据验证

已验证官方中文点位源：当前缓存 88,073 条点位和 47 条推荐路线。`render` 现在输出 PNG；`src/bridge.js` 返回可供机器人转换为合并转发的文本和图片节点。生成的 `data/*.json` 与 `cache/` 属于运行时数据，默认不进入 Git。

## 官方底图

执行 `node src/cli.js map 遗迹守卫` 会使用官方 P0 WebP 切片生成带底图 PNG。切片并发限制为 8，单片最多重试 3 次；请求带 15 秒超时，切片成功率低于 85%、点位覆盖异常或属于附加地图层时自动退回坐标路线图。地图元数据缓存 12 小时，更新失败时继续使用最近一次有效元数据。
